# Prometheus 指标快照

`rmqtt-http-api` 的 Prometheus 接口读取后台生成的指标快照。HTTP 抓取和节点间快照请求只读取已编码的缓存，不在请求期间采样、渲染指标或等待集群查询。快照用于只读监控，允许指标暂时不可用；它不参与 MQTT 消息处理、Raft 成员管理或集群恢复决策。

## 接口与缓存

接口路径和 `node` 标签沿用原有约定：

| GET 路径 | 返回内容 |
| --- | --- |
| `/api/v1/metrics/prometheus/sum` | 完整集群合计，`node="all"` |
| `/api/v1/metrics/prometheus` | 各节点指标及完整集群合计 |
| `/api/v1/metrics/prometheus/{id}` | 指定节点的可用快照；请求本机 ID 时直接读取本地快照 |

集群接口和远端节点接口只发出合并后的后台刷新通知，立即读取现有缓存。增加抓取频率不会为每个请求创建采集任务。本地快照可以独立于集群刷新提供服务。

缓存尚未初始化、过期、指定节点不可用、缓存暂时被占用或采集 worker 已停止时，接口返回 HTTP `503 Service Unavailable`。首次抓取可能触发异步初始化，因此启动后前一至两次抓取可能缺少指标；这不是预热完成时间的保证，混合版本或节点故障可能使缺口持续更久。

## 采样周期与资源边界

在 `plugins/rmqtt-http-api.toml` 中配置集群刷新间隔：

```toml
# 默认 30 秒；最短 30 秒，建议 30～60 秒。
prometheus_metrics_cache_interval = "30s"
```

已有配置中的 `"5s"` 等较小值按 30 秒处理，更长的配置值继续生效，不会擅自提高采集频率。超过 120 秒的刷新间隔可能在两轮刷新之间使聚合缓存过期并返回 503。该配置不改变下表的本地或操作系统采样周期。集群刷新按请求触发，刷新完成后至少等待配置间隔才开始下一轮；没有请求时不主动轮询集群。

| 项目 | 行为或上限 |
| --- | --- |
| 本地业务计数器快照 | 约每 10 秒采样一次 |
| 操作系统负载、内存、磁盘 | 最多每 60 秒尝试一次，独立阻塞任务执行 |
| 集群采集 | 每个监控器使用一个专用 worker，最多同时请求 2 个远端节点 |
| 远端请求 | 单次 unary RPC 超时 1 秒，整轮远端采集预算 3 秒；失败节点退避重试 |
| 注册监控目标 | 最多 128 个节点，包括本机 |
| 单节点传输快照 | 最多 256 KiB 序列化负载，回复另有少量协议封装 |
| 渲染后的集群缓存 | 各节点视图、全部视图与合计视图总计最多 8 MiB |
| 可服务的快照年龄 | 从源采样时间计算，最长 120 秒 |
| 同时持有指标响应体 | 最多 32 个；读取后续响应块超过 10 秒则停止发送 |

8 MiB 是渲染后的集群缓存大小限制，不是 RMQTT 进程总内存或瞬时分配的上限。超过目标数、数据大小或时间预算时，本轮刷新可以失败，现有缓存继续遵循原来的过期时间。

响应许可跟随 HTTP 响应体直到消费或丢弃，避免慢客户端无限保留旧版本快照。传输受背压而不再轮询响应体时，10 秒检查不能主动中断整个连接，但 32 个许可仍限制被持有的响应数量；超限抓取快速返回 503。

操作系统调用尚未结束时，不排队创建替代调用。其并发许可跟随实际阻塞操作，在该操作结束前保持占用。监控 worker 退出或 panic 后不会自动增生替代 worker，后续指标请求返回不可用。

## 节点故障与不完整刷新

监控目标来自注册的监控节点地址，不通过实时健康或 membership 查询筛除故障节点。`sum` 和全部视图只有在本轮取得所有预期节点的有效快照时才更新，不将部分节点的合计伪装成完整集群合计。

如果刷新不完整，先前完整的视图可以继续返回，直到其中最早的源快照达到 120 秒。失败刷新和重复抓取都不会延长这个期限。没有先前完整视图或缓存已经过期时，`sum` 和全部接口返回 503；已经取得的单节点视图仍可在有效期内读取。检测到监控目标集合变化或节点进程启动时间变化时，旧的完整视图会失效，等待重新收齐数据。

一次完整刷新表示所有预期节点都提供了有效快照，不表示所有可选字段都有值，也不表示集群或 MQTT 业务健康。HTTP 200 也可能来自尚未过期的旧完整视图。

## 指标缺失与数据时效

采样对扩展锁只做非阻塞尝试；忙碌或不可用的统计源可以省略对应 `rmqtt_stats` 字段。合计中任一节点缺失的字段也会省略，避免把不完整值当作总量。缺失字段不应在仪表盘中默认解释为零。

握手活跃数通过只在监听器创建时更新的监控名单读取已有原子计数，不遍历业务 DashMap。`handshakings_rate.count/max` 不再采集：依赖库的速率 getter 内部使用同步互斥锁，外层 `now_or_never` 不能阻止它等待。正常握手、限流和管理接口的速率查询不变。

Raft 监控节点名单随节点注册、地址更新和移除同步维护；采集只尝试读取监控副本，不遍历业务节点或 gRPC client 表。名单忙碌、恢复未完成、失败或取消时，本轮集群刷新失败，不把部分名单当作完整小集群。失败恢复后的监控名单在后续完整恢复成功后重新可用。

主题数、路由数和聚合规则一起采样，渲染阶段不再读取 Router 或调用其方法。Raft/默认路由保留“当前数取最小、峰值取最大”的规则，broadcast 保留求和规则。未知路由实现、无法采样或节点间规则不一致时，相关指标省略，不影响其他指标。监控只读快照，不改变路由处理逻辑。

存储统计只调用插件显式提供的非阻塞内存快照接口，不调用可能访问数据库的 `count/max/len`。不支持安全快照的存储插件，其 retaineds/message_storages/delayed_publishs 对应字段可以缺失。内存 Retainer 和内置延迟队列提供只读快照；消息收发和存储处理逻辑不变。

操作系统数据独立缓存。尚未取得系统样本时不导出负载、内存和磁盘字段；渲染时发现系统样本已超出 120 秒有效窗口，也会省略这些字段。包含系统值的缓存同时受系统源时间的 120 秒期限限制，不因业务计数器刷新而延长。

旧的 `rmqtt_nodes{item="running"}` 不再由这条监控路径采集或导出，因为它需要实时健康查询。现有健康检查、readiness、liveness 及管理接口的实时语义不因快照机制改变；需要健康信号的规则应使用相应接口或探针。

成功的 Prometheus 响应包含以下元数据：

| 指标 | 含义 |
| --- | --- |
| `rmqtt_metrics_refresh_success` | 最近一轮集群刷新是否收齐快照，1 为完整、0 为不完整 |
| `rmqtt_metrics_expected_nodes` | 最近已知的注册监控目标数 |
| `rmqtt_metrics_missing_nodes` | 最近一轮集群刷新缺少的目标数 |
| `rmqtt_metrics_snapshot{node="…",item="sampled_at_seconds"}` | 业务快照的源 Unix 时间，单位秒；合计取所有节点中最早的时间 |
| `rmqtt_metrics_snapshot{node="…",item="system_sampled_at_seconds"}` | 操作系统样本的源 Unix 时间；没有系统样本时省略，合计需要所有节点都有系统样本 |
| `rmqtt_metrics_snapshot{node="…",item="omitted_stats"}` | 快照中记录的省略统计字段数；不覆盖所有渲染阶段的省略情况 |

刷新元数据描述集群刷新状态，即使它随单节点视图返回，也不等同于该节点的实时健康。接口返回 503 时不保证还能抓取到这些元数据，应同时关注 Prometheus 的 `up`。

Prometheus 为本次抓取附加的时间戳不能表示源数据的新鲜程度。可用以下 PromQL 分别查看业务和系统样本年龄：

```promql
time() - rmqtt_metrics_snapshot{item="sampled_at_seconds"}
```

```promql
time() - rmqtt_metrics_snapshot{item="system_sampled_at_seconds"}
```

`node="all"` 的年龄反映对应合计中最老的样本。节点时钟应同步；来自明显未来时间的快照会被拒绝。缺少时间序列与年龄较大是不同情况，告警规则应同时考虑缺失和抓取失败。

## 升级与适用范围

该机制随 RMQTT 镜像及其 `rmqtt-http-api` 插件发布，不要求升级 Operator。Prometheus 路径、ServiceMonitor 和 HTTP 插件的认证配置可以沿用。

节点间使用 `MetricsSnapshotV2` unary 协议读取预先编码的本地快照，其中携带路由聚合规则。保留旧消息编号，但不将 V1 负载解释为 V2，也不回退到旧版实时指标采集或业务 gRPC 重连队列。滚动升级期间，不支持该协议的旧节点按缺失目标处理，因此完整集群指标可能暂时返回 503，直到所有目标具备兼容实现并重新收齐快照。升级后的本地节点视图仍可独立可用。

设计通过专用 worker、缓存读取、非阻塞锁尝试和采集预算减少监控对核心路径的干扰。后台采样仍会读取共享计数器并调用扩展统计源，不能据此宣称零性能开销、任意负载下无影响或生产环境吞吐保证。本文描述设计与接口行为，不构成任何环境上线压测或故障恢复验证的结论。
